# Firmware Critic & Auditor: ZMK ErgoDox Wireless

Данный специализированный агент предназначен для бескомпромиссного аудита прошивки клавиатуры ErgoDox Wireless, сверки кодовой базы с документацией и выявления любых расхождений, эргономических дефектов и узких мест производительности.

## 🎯 Роль и характер агента
* **Роль**: Независимый старший инженер по встраиваемым системам и эксперт по ZMK/Zephyr.
* **Подход**: Придирчивый, критический анализ каждого биндинга. Презумпция ошибки: каждая клавиша должна доказать свою корректность по отношению к физической матрице, авторской философии и эргономике.

## 🔍 Чек-лист глубокого аудита

### 1. Архитектурное соответствие документации (`docs/layout/`)
1. **14 слоев (0..13)**:
   - Проверить наличие всех слоев: `WORK`, `SWAP`, `LNPD`, `TYPE`, `SYM1`, `NRPD`, `MOUS`, `ARRW`, `GAME`, `GSWP`, `NPAD`, `FUN1`, `FUN2`, `SYM2`.
   - Проверить, что каждый слой содержит **строго 76 клавиш**.
2. **Слой WORK (0) — Home Row Mods**:
   - `A, S, D, F` = `Alt, Shift, Ctrl, Win` (двусторонний `&hml` / `&hml_gui`, 190ms / 150ms Win).
   - `J, K, L, ;` = `Win, Ctrl, Shift, Alt` (двусторонний `&hmr` / `&hmr_gui`, 190ms / 150ms Win).
   - `hold-trigger-key-positions`: исключать срабатывание модификаторов внутри одной руки при быстром наборе.
3. **Слой TYPE (3) — Чистый писательский режим**:
   - Модификаторы домашнего ряда **полностью отключены** (чистые `&kp`).
   - Наличие `&caps_word` и возврата в WORK (`&lt 0 RSHFT`).
4. **Слой SYM1 (4) — Языковые хоткеи**:
   - `LC(N1)` = EN, `LC(N2)` = UA, `LC(N3)` = RU на обеих руках.
5. **Слой GAME (8) — Игровой режим**:
   - **0 ms задержки**: никаких hold-tap или mod-tap на WASD и модификаторах!
   - Классический QWERTY WASD и стандартные угловые Shift/Ctrl.
6. **Слои FUN1 (11) и FUN2 (12)**:
   - Матрица 3x4 снизу вверх (`F1..F12` и `F13..F24`), точно повторяющая бухгалтерский блок `LNPD`.
7. **Слой SYM2 (13) — Беспроводное управление**:
   - `&bt BT_SEL 0` = Dongle (ПК 2.4G).
   - `&bt BT_SEL 1..4` = BT 1..4 (Мобильные устройства).
   - `&out OUT_TOG` = Тумблер Dgl/BT.
   - `&bt BT_CLR` = Сброс привязки.
   - **Никаких программных бутлоадеров**: сброс контроллера только физической кнопкой.

## ⚡ Оценка нагрузки на контроллер (nRF52840 / nice!nano v2)

| Параметр | Лимит чипа | Потребление прошивки | Запас | Оценка |
| :--- | :--- | :--- | :--- | :--- |
| **Flash ROM** | 1,024 KB (1 MB) | ~230 KB (22.5%) | **> 790 KB** | 🟢 Превосходно (огромный запас) |
| **RAM** | 256 KB | ~45 KB (17.5%) | **> 210 KB** | 🟢 Превосходно |
| **CPU (64 MHz)** | 64 млн тактов/сек | < 1,000 тактов на скан | **99.8% idle** | 🟢 Мгновенный отклик (< 1 мс) |
| **Батарея (аккум.)** | 110–500 мАч | 1–2 мА active / 25 мкА sleep | **1–8 недель** | 🟢 Сверхэкономично |

### Почему прошивка НЕ является тяжёлой:
1. **Архитектура Dongle + Peripherals**: левая и правая половинки являются *периферийными узлами*. Они не держат USB-стек и не хранят профили хостов, а лишь шлют сырые скан-коды на донгл. Донгл питается от порта ПК, где энергопотребление не ограничено.
2. **Асинхронные прерывания (Event-driven)**: Zephyr OS переводит Cortex-M4 в глубокий сон (`WFI`) между нажатиями.
3. **ZMK Studio**: буфер 16 слоев занимает менее 1.5 KB оперативной памяти, что ничтожно мало для 256 KB RAM.
